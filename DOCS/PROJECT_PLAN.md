# PROJECT_PLAN.md

## 1. 프로젝트 개요

**프로젝트명:** ALOHA Slide Studio  
**목표:** 개발 강의와 기술 문서에 최적화된 웹 기반 프레젠테이션 편집기 구축  
**초기 운영 방식:** 브라우저 Local-first, 서버 없이 동작  
**기준 캔버스:** 1280 × 720px, 16:9

초기 개발은 한 번에 모든 기능을 구현하기보다 편집·저장·복원 흐름을 먼저 완성하고, 코드 요소와 발표·내보내기 기능을 순차적으로 확장합니다.

## 2. 제품 범위

### 초기 목표(MVP)

- 프레젠테이션 생성·열기·이름 변경·삭제
- 슬라이드 생성·복제·삭제·순서 변경
- 16:9 캔버스와 확대/축소
- 텍스트·이미지·도형 요소 추가 및 편집
- 캔버스에서 요소 선택·이동·크기 조절
- 속성 패널에서 위치·크기·스타일 수정
- Zustand 기반 상태 관리
- IndexedDB 기반 자동 저장
- JSON 프로젝트 내보내기·가져오기
- 기본 실행·빌드·린트 확인

### 후속 목표

- 슬라이드 마스터·레이아웃·테마 관리
- Monaco Editor 기반 코드 요소 편집
- 언어별 구문 강조 및 코드 테마
- 실행·발표 모드
- 요소 애니메이션과 슬라이드 전환
- PPTX 및 PDF 내보내기
- 실행 취소·다시 실행, 다중 선택, 그룹화, 레이어 관리
- 템플릿 라이브러리와 재사용 가능한 요소

### 초기 범위에서 제외

- 실시간 다중 사용자 공동 편집
- 사용자 계정·조직·권한 관리
- 서버 동기화 및 클라우드 저장
- 댓글·승인·버전 협업 워크플로
- AI 자동 슬라이드 생성

위 항목은 MVP 안정화 이후 별도 요구사항과 아키텍처 검토를 거쳐 추진합니다.

## 4. 단계별 상세 작업

### 0단계: 프로젝트 기반

- [ ] React + TypeScript + Vite 프로젝트 초기화
- [ ] ESLint 및 포맷 규칙 설정
- [ ] Tailwind CSS 및 shadcn/ui 연결
- [ ] 폴더 구조와 앱 레이아웃 생성
- [ ] 공통 타입 및 기본 테마 토큰 작성
- [ ] 개발 서버와 프로덕션 빌드 확인

**완료 조건:** 신규 개발 환경에서 설치·실행·빌드가 가능하고, 기본 편집기 레이아웃이 표시됩니다.

### 1단계: 편집기 MVP

- [ ] 프로젝트 목록 및 새 프로젝트 생성
- [ ] 슬라이드 목록과 CRUD
- [ ] 1280 × 720 기준 캔버스 및 반응형 스케일링
- [ ] 텍스트 요소 추가·선택·이동·크기 조절
- [ ] 도형 요소 추가·스타일 변경
- [ ] 이미지 업로드 및 배치
- [ ] 요소 속성 패널
- [ ] Zustand 스토어 분리
- [ ] IndexedDB Repository 구현
- [ ] JSON 백업·복원

**완료 조건:** 프로젝트를 생성하고 최소 3개 슬라이드를 구성한 뒤 새로고침 후에도 콘텐츠가 유지됩니다. JSON 파일을 통해 다른 브라우저 세션에서 복원할 수 있습니다. 이미지가 포함된 백업은 이미지 데이터까지 복원되어야 합니다.

### 2단계: 마스터·레이아웃·테마

- [ ] 마스터 데이터 모델과 렌더러
- [ ] 공통 배경·로고·푸터 요소 관리
- [ ] 레이아웃 placeholder 모델
- [ ] 슬라이드에 마스터·레이아웃 연결
- [ ] 테마 색상·폰트·기본 스타일 적용
- [ ] 기본 레이아웃 템플릿 제공

**완료 조건:** 마스터 또는 테마 변경이 해당 설정을 참조하는 슬라이드에 일관되게 반영됩니다. 슬라이드별 콘텐츠는 보존되어야 합니다.

### 3단계: 코드 블록

- [ ] CodeElement 타입과 생성 함수
- [ ] Monaco Editor 통합
- [ ] 언어 선택 및 코드 편집

- [ ] 코드 테마·폰트·줄 번호·줄바꿈 설정
- [ ] 긴 코드와 가로/세로 오버플로 처리

**완료 조건:** Java, Python, JavaScript, TypeScript, SQL 등 주요 언어 코드가 편집·표시·저장됩니다. 발표 모드에서는 편집 UI 없이 읽기 전용 코드로 표시됩니다.

### 4단계: 발표 및 애니메이션

- [ ] 키보드 방향키·Space·Esc 입력 처리
- [ ] 요소 등장 애니메이션
- [ ] 클릭 순서 및 지연 시간 설정
- [ ] 슬라이드 전환 효과
- [ ] 발표 중 애니메이션 초기화·재생 제어

**완료 조건:** 슬라이드 순서와 애니메이션 순서가 예측 가능하게 실행되고, 편집기 상태를 손상하지 않습니다.

- [ ] 코드 블록 내보내기 표현 방식 결정
- [ ] 마스터·테마·배경 매핑
- [ ] PDF 출력 방식 결정 및 구현
- [ ] 폰트 대체·줄바꿈·페이지 경계 검수

### 6단계: 편집 품질

- [ ] 그룹화·그룹 해제
- [ ] 레이어 목록 및 순서 변경
- [ ] 단축키 도움말

## 5. 품질 기준(Definition of Done)

기능을 완료 처리하려면 다음 항목을 확인합니다.

- 관련 TypeScript 타입 오류가 없습니다.
- 정상 입력과 잘못된 입력에 대한 동작이 정의되어 있습니다.
- 저장·복원 후 데이터가 동일하게 유지됩니다.
- 새 기능이 기존 요소의 편집·발표·내보내기 흐름을 깨뜨리지 않습니다.
- 주요 동작에 단위 테스트 또는 수동 검증 절차가 있습니다.
- `npm run build`가 성공합니다.
- 문서(`TASKS.md`, `CHANGELOG.md`, 필요 시 `DATA_MODEL.md`)가 갱신되어 있습니다.

## 6. 위험 요소와 대응

| 위험 | 영향 | 대응 |
|---|---|---|
| PPTX와 브라우저 렌더링 차이 | 내보낸 문서의 위치·폰트·줄바꿈 차이 | 공통 좌표계, 변환 어댑터, 샘플 회귀 테스트 |
| 폰트 미설치 | 다른 PC에서 디자인 변경 | 기본 폰트 스택 지정, 폰트 대체 안내 |
| 이미지가 포함된 JSON 용량 증가 | 백업 파일이 커짐 | 이미지 압축·크기 제한·ZIP 번들 검토 |
| 캔버스 요소 수 증가 | 렌더링 성능 저하 | 필요한 영역만 렌더링, 메모이제이션, 성능 측정 |
| 편집 상태와 저장 데이터 불일치 | 데이터 유실 | Repository 추상화, 저장 큐, 복원 테스트 |
| 라이브러리 API 변경 | 빌드 또는 기능 장애 | 버전 고정·의존성 업데이트 점검 |

- 프로젝트 버전 관리
